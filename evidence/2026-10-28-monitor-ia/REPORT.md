# 实时监测页信息架构整改（APP 1.0.11，2026-10-28）

## 1. 用户反馈

> “APP 的检测页面怎么分类的，为什么是混乱的，门磁等等的界面都是混乱的。”

核实属实：1.0.10 的实时监测页同时用了两套分类，并且把“未配置能力”也渲染成卡片，导致页面看起来混乱。

## 2. 原实现（1.0.10）为什么乱

1. **两套分类维度混用**：页面既按“房间”分组，又提供一行全局“传感器类型”筛选
   （全部/温湿度/活动/燃气/烟雾/门窗）。切到“门窗”后，没有门磁的房间整块消失，
   房间块忽隐忽现；筛选 chip 还横向溢出（“门窗”被截断），用户无法预期页面结构。
2. **未配置能力也占卡片**：客厅没有 PIR，却渲染“PIR 活动监测 / 未配置 PIR，无活动监测”
   卡片；同时摄像头判定是另一张卡。一个房间出现“没有这个设备却有一张它未配置的卡”。
3. **同一状态重复四遍**：门磁卡片同时出现
   标题“门磁” → 值“上次读数 开启” → 标签“离线·上次读数” → 页脚“厨房 · 3 小时前”
   → 说明“设备离线，展示上次读数…；暂无开启记录”，同一件事读五遍。
4. **值和状态自相矛盾**：门磁值为“开启”，说明却写“暂无开启记录”；
   摄像头卡片值“暂无有效检测数据”，状态也是“暂无有效检测数据”。
5. **图标不可靠**：部分模拟器上 `SymbolGlyph` 渲染成空白方块（温湿度/活动图标只剩绿色底）。
6. **滚动层级割裂**：说明文字在滚动区外固定，滚动时内容从半张门磁卡片开始，像“页面被切断”。

## 3. 1.0.11 的新分类（只保留一套维度）

```text
实时监测
└─ 房间（厨房 / 卫生间 / 客厅 / 随身求助）
   └─ 设备（名称 + 在线/离线 + 最近上报）
      ├─ 环境：温湿度、燃气、烟雾
      └─ 活动与安防：人体活动（PIR）/摄像头人体检测（非 PIR）、门磁、紧急求助、跌倒、水漏
```

规则：
- **房间是唯一一级分类**；删除全局“传感器类型”筛选，不再出现两套分类互相切换。
- **未配置/未安装能力不再出现在监测页**（`state=unsupported` 过滤掉），统一到“设备管理”看能力清单；
  客厅只保留“摄像头人体检测（非 PIR）”一行，不再出现“未配置 PIR”卡。
- **同一状态只说一次**：设备离线由设备块横幅说明，行内只标“上次读数”；删除每行重复的“房间 · 时间”页脚。
- **门磁语义修正**：开启且没有最近开启时间 → “开启时间未知”；关闭且无记录 → “暂无开关记录”；
  值“开启”时状态为“关注”，不再出现“开启 + 暂无开启记录”的矛盾。
- **值和状态不重复**：两者相同时状态自动改为“待确认”。
- **图标改为单字色块**（温/气/烟/人/门/视/求/水/跌），避免 SymbolGlyph 空白方块，也便于老人识别。
- 燃气/烟雾说明去掉与状态列重复的“报警未启用”，只保留“未标定 · 原始 ADC 不代表 ppm/安全”。
