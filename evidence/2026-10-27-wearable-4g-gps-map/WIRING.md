# 随身 SOS 最终接线表（ESP32-S3 + M100MG-B1）

> 适用板：ESP32-S3（CH343，MAC `30:30:f9:08:76:84`，N16R8）+ YED-M100MG-B1（YED-M-Test-B 底板）。
> 本表是**唯一**接线口径；与此前任何历史版本冲突时以本表为准（例如 GPIO6 蜂鸣器旧说法已废弃）。

## 1. ESP32-S3 ↔ M100 串口（硬件 UART1）

| ESP32-S3 引脚 | 方向 | M100 引脚（底板丝印） | 说明 |
|---|---|---|---|
| **GPIO17**（UART1 TX） | → | **RXD** | ESP32 发送，接模块接收 |
| **GPIO18**（UART1 RX） | ← | **TXD** | 模块发送，接 ESP32 接收 |
| **GND** | ↔ | **GND** | **必须共地**，否则串口不可靠/无数据 |

- 电平：M100 串口兼容 3.3V/5V；ESP32-S3 为 3.3V，直连即可，无需电平转换。
- 参数：115200、8 数据位、无校验、1 停止位、无流控。
- 可选（不接也能演示）：M100 `RDY`(3.3V，联网后高电平) → 任意空闲 GPIO 做“网络就绪”指示；本轮固件不依赖它。
- RST/DTR 不接。

### 关于底板的 USB 数据线（重要）

YED-M-Test-B 底板的 USB-TTL 与模块 UART 在板上相连。**最终运行/验收时，M100 底板只插 DC 5~12V 电源，不要插 USB 数据线**，
否则板载 CH340 的 TX 会与 ESP32 的 GPIO17 同时驱动模块 RXD，造成冲突。配置参数时才插 USB 数据线，配置完拔掉。

## 2. 供电

| 器件 | 供电 | 说明 |
|---|---|---|
| M100 / 测试底板 | **DC 5~12V（建议 12V/1A，≥10W）** 插底板 DC 座 | **禁止用 ESP32 的 3.3V 给 M100 供电** |
| ESP32-S3 | USB 5V（充电宝/电池组，USB-A→USB-C） | 最终验收脱离电脑，用充电宝即可 |
| 共地 | ESP32 GND ↔ M100 GND 必须一根线连通 | 两块电源各自独立时尤其重要 |

## 3. 按钮

| 器件 | 接线 | 说明 |
|---|---|---|
| 轻触按钮 | 一脚 → **GPIO4**，另一脚 → **GND** | 内部上拉，**低电平=按下**；固件 20ms 采样 + 60ms 消抖 |
| 上拉 | 无需外接 | 使用 ESP32 内部上拉 |

## 4. 蜂鸣器

| 器件 | 接线 | 说明 |
|---|---|---|
| 有源蜂鸣器（3 针模块） | `I/O` → **GPIO5**；`VCC` → **3.3V**；`GND` → **GND** | 已实测**高电平触发**（I/O=1 响，I/O=0 静音） |

## 5. 禁止事项

- **GPIO6 严禁复用**：该板 GPIO6 是 SPI Flash 引脚，电平被底层覆盖（历史长鸣问题的根因）。
- 不要用 GPIO19/20（USB）、GPIO26~37（Flash/PSRAM/晶振）。
- 不要给 M100 供 3.3V；不要共用一个会掉压的 USB 口同时带 M100 和 ESP32。
- 不要把 M100 的 RXD/TXD 接到 ESP32 的 3.3V/5V。

## 6. 上电顺序

1. 接好所有线，确认 M100 只插 DC、不插底板 USB。
2. 先给 M100 上电，等 NET 灯约 1000ms 慢闪（已连服务器）。
3. 再给 ESP32 上电/按复位。
4. ESP32 串口（USB，调试时接电脑 COM8）应打印 `M100 链路` 相关日志与周期心跳；有网络时 MQTT 主题上能看到 `hb`。

## 7. 判断“通没通”的现场标志

| 现象 | 含义 |
|---|---|
| M100 NET 1000ms 慢闪 + RDY 常亮 | 4G 已连上我方 Broker |
| ESP32 按下按钮蜂鸣 3 短声 | 本地求助已生成 |
| APP 出现「随身求助」告警 | 上行链路成功（ESP32→M100→MQTT→后端） |
| APP 点确认后 5~10 秒内设备停响 | 下行 ACK 成功（APP→后端→MQTT→M100→ESP32） |
| 设备响 30 秒后自动静音但 APP 仍显示待确认 | 正常：静音≠已确认 |
| APP 一直“等待设备确认”超过 1 分钟 | 下行可能丢失：见 `README.md` §5.1 的适配器重启恢复步骤 |

## 8. 实测结论（2026-10-27）

1. **UART 电平**：ESP32 3.3V 直接对接 M100 UART 可正常双向通信，无需电平转换。
2. **M100 底板 USB-TTL 必须拔掉**：实测插着时 CH340 TX 与 ESP32 GPIO17 同时驱动 M100 RXD，
   上行被阻断（拔掉后立即恢复）。所以最终形态是「M100 只接 DC，ESP32 只接充电宝」。
3. **M100 下行不追加换行**：服务端下发必须 `JSON + "\n"`，固件同时有 100 ms 空闲成帧兜底。
4. **GPS 上报格式**：`经度_纬度`（WGS84 十进制，如 `112.55326080300_32.966827393000`），
   无时间字段；`fixTime` 由服务端接收时间决定，APP 按 WGS84→GCJ-02 转换一次。
5. 上电顺序：先 M100，等灯态正常，再 ESP32；两块电源独立时必须共地。
