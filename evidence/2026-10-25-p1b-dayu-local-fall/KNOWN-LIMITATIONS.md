# 已知限制

1. **无法完成真机姿态验收（核心限制）**
   - DAYU 相机抓到的是 640×480 正面近景；真实帧只有头/肩高置信度，hips conf≈0.01–0.02，validKptCount≈6–8。
   - 现场空间不足，用户无法后退到全身（头到脚）入镜；因此不能真机验证 UPRIGHT/SITTING/HORIZONTAL 与缓慢躺下/恢复。
   - 本轮不伪造真机动作，也不把 fixture 当真人跌倒。

2. **APP 预览显示方向与抓帧方向不一致**
   - 用户看到预览旋转 90°；实际 JPEG 经人工核对为方向正常的正面近景（EXIF 无 orientation）。
   - `--rotate 0` 可得到高置信度头/肩点；`--rotate 90/270` 大量帧丢检，故不能靠软件旋转修复预览显示。
   - 未修改 APP/HAP；这是显示层问题，后续 APP 迁移时应一并修正。

3. **性能**
   - 320 图像级 p50 399 ms、p95 411 ms、2.23 FPS；真实相机 20.3 分钟 p50 462 ms、p95 484 ms、2.05 FPS、errors 0。
   - 416/640 不满足 ≥2 FPS / p95≤700 ms；只有 320 过性能闸门。
   - CPU_ONLY；ncnn 当前构建约 1 核，多线程 1/2/4 无扩展。NPU 无驱动/运行库，未使用、不能声称 RKNN/NPU。

4. **跌倒功能边界**
   - 状态机/跟踪/姿态/时序仅在 fixture 中验证（13/13）；真机身体关键点不足，未完成真实姿态状态机验收。
   - 快速下降→持续横卧、重复事件抑制、恢复后新事件等只有 **FIXTURE** 证据；没有真人快速跌倒，也没有显示器视频证据。
   - `fall=true` 只在本地 FALL_CONFIRMED 事件；APP HTTP 仍固定 fall=false/fallEvaluated=false，未接正式告警。
   - 没有 MQTT/backend/homemon/APP 集成；没有 ACK/SOS/4G。

5. **模型/数据**
   - YOLO11n-pose 为 AGPL-3.0；正式分发需另做许可证合规。
   - 测试图来自项目既有证据；真实相机帧只在设备候选目录临时保存，证据不包含图像。
   - personCount 来自有效推理，但近景/遮挡下可能有误检；没有用大量真实场景做误报率统计。

6. **运行环境**
   - 只在 DAYU200（OpenHarmony 7.0.0.38/arm32 musl）验证；未覆盖其他设备/系统版本。
   - 相机取帧依赖正式 APP 打开相机页（用户操作），未常驻、未上电自启。

7. **P0 现场外部重启**
   - P1-B 期间 fport 曾丢失，已重建；模拟器/APP 曾消失后自动重启（Emulator PID 67520 自 02:18:57，APP PID 5698 自 02:19:11）。
   - P0-B 冻结时的同一 PID 26710 实例已不成立；P0 当前可用但需用户按基线重新确认，不是本任务启动。
