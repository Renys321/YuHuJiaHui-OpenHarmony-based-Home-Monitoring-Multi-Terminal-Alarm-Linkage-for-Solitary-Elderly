## 3. ESP32 摄像头引脚占用

| 信号 | GPIO |
|---|---:|
| `OV_D0..D3` | 4、5、6、7 |
| `OV_D4..D7` | 15、16、17、18 |
| `OV_VSYNC` | 47 |
| `OV_HREF` | 48 |
| `OV_PCLK` | 45 |
| `OV_SCL` | 38 |
| `OV_SDA` | 39 |

当前固件配置为 PIR=`GPIO4`、门磁=`GPIO5`、外接蜂鸣器=`GPIO6`。三路与摄像头数据线直接
冲突。启用 ESP32 摄像头前必须完成以下工作：

当前固件会把 GPIO6 配置成输出；摄像头插入 P2 后，GPIO6 同时是摄像头的 `OV_D2` 输出。
两端同时驱动可能产生电气争用。在迁移或禁用 GPIO4/5/6 并重新烧录之前，不得插入摄像头。

1. 从原理图确认新的可用输入 GPIO，并重新接 PIR、门磁。
2. 决定继续使用外接蜂鸣器，或实现 XL9555 后改用板载蜂鸣器。
3. 在 `sdkconfig` 中启用并验证 8 MB PSRAM，重新设计分区表。
4. 引入经过验证的 ESP-IDF 摄像头组件和对应 OV2640/OV5640 配置。
5. 独立验证 JPEG 抓拍、内存峰值、Wi-Fi 共存和断线恢复。

若确定 ESP32 也要接摄像头，保守的第一版可在不使用 SPI LCD/无线模块时把 PIR 和门磁迁到
GPIO11、GPIO12，并把蜂鸣器改为 XL9555 P0_3。GPIO35、GPIO36、GPIO37 虽在表中标为独立，
同时明确标注“勿用”，不能作为迁移目标。GPIO11/12 方案仍需先用原理图和实物电平验证，不能
直接作为已验收接线。

完成这些步骤前，不能把 OV5640 资料外推为项目已经具备 ESP32 摄像能力。

## 4. DAYU200 摄像头

本地 DAYU200 资料确认摄像头接口为 MIPI-CSI2，支持 1x4-lane 或 2x2-lane，速率为每 lane
2.5 Gbps。当前 OpenHarmony 7.0 镜像的设备树资源高度指向启用的 GalaxyCore GC8034、
`RK-CMK-8M-2-v1` 模组和 `CK8401` 镜头；这只是固件适配证据，实际模组仍需上板枚举。

系统镜像和签名 syscap 包含 `SystemCapability.Multimedia.Camera.Core`，SDK 26 提供 Camera Kit。
当前监护 APP 已声明 `ohos.permission.CAMERA` 并实现用户主动授权与设备枚举；系统相机已真机
完成预览和取帧。当前自研 APP 已完成用户主动开启/关闭的 640×480 预览和手动 JPEG 拍照；
告警抓拍、连续帧送入 YOLO 和 DAYU 真机推理仍未完成。

推荐按以下顺序实现：

1. 已完成：确认相机服务、`rkisp_v5`、`/dev/video0`、系统预览与连续取帧。
2. 已完成：最终监护 APP 的 CAMERA 授权与 `getSupportedCameras()` 枚举 1 台设备。
3. 已完成：在 APP 内实现用户主动开启/关闭的可见预览和手动拍照。
4. 部分完成：照片已保存到 APP 私有目录；APP 内照片列表、查看和删除入口尚未实现。
5. 最后增加默认关闭的“告警抓拍”，只允许摄像头所属房间、前台、用户已授权且新 alarmId
   首次出现时拍摄一张；以 alarmId 去重。

相机权限被拒绝、相机列表为空或抓拍失败时，原有监护、语音和 ACK 闭环必须继续工作。

## 5. 隐私和验收边界

- 不实现后台静默摄像。
- 自动抓拍默认关闭，需用户显式授权并可随时关闭。
- 图片先保存在 APP 私有目录，提供查看和删除入口，不自动上传公网。
- DAYU 摄像头只代表其实际安装房间，不跨房间制造错误现场证据。
- 当前不宣称 AI 跌倒识别。摄像头首期只承担现场查看和告警抓拍。
- 图片识别工具本轮返回 403，因此没有根据资料图片外观猜测摄像头型号；型号结论来自固件资源和文字资料。

## 6. YED-M100MG-B1 4G/GNSS

资料确认模块支持 Cat.1 数据、TTL UART、MQTT/HTTP/WebSocket 与 SSL，并列出 OneNET；独立 GNSS 为选配，实际可能是 GPS/北斗多模或北斗单模。供电范围为 5-12 V、资料标称 10 W，不能默认由 USB-TTL 直接供电。详细接线、脱敏串口探测和验收门禁见 `hardware/yed-m100mg-b1/README.md`。

GNSS 使用 WGS84，室内可能无法获得有效定位。上传时必须同时携带 `valid` 与 `fixTime`，不能把无效定位伪装成 `(0, 0)`。公开资料未列出音频引脚、麦克风或扬声器，因此当前只把模块用于数据、定位和可选短信。
